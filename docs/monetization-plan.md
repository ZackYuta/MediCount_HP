# 服用記録カウンター 買い切り計画(ファミリー / プロ / セット)

作成日: 2026-10-26 / 改訂: 価格を ¥600 / ¥1,200 / ¥1,500 に変更、iCloud同期は対象外、薬の登録数は無料のまま無制限、HealthKit entitlement は削除、**商品は3つに絞る(補完商品・人数の追加枠は要望が来るまで見送り)** / 対象: iOSアプリ「服用記録カウンター」(v3.01.03)

## 1. 方針サマリ

| 項目 | 内容 |
|---|---|
| 課金モデル | 買い切り(非消耗型)3商品。サブスクなし、バナー広告なし |
| 無料 | 現行の基本機能(薬の登録数も無制限のまま) |
| ファミリー | 日本 ¥600 / 海外 $5.99(5人まで) |
| プロ | 日本 ¥1,200 / 海外 $11.99 |
| セット(ファミリー+プロ) | 日本 ¥1,500 / 海外 $14.99 |
| 見送り | 人数の追加枠、補完商品(買い足し割引)。要望が出てから検討 |
| iCloud | **同期は提供しない / Appleのファミリー共有も有効にしない** |
| 差別化軸 | 「データは端末内のみ」「広告なし」「サブスクなし」 |
| 最重要の配慮 | **既存ユーザーの現行機能は取り上げない**(登録数も無制限のまま) |

競合調査では、日本の服薬アプリは年額2,500円前後・月額500〜600円・広告削除300円が相場で、吸入薬・点鼻薬に特化した日本語アプリは見当たらなかった。今回の価格(特にプロ¥1,200、セット¥1,500)は相場より高めの設定になる。**実測データがないため、結果を見て調整する前提**で進める(7章)。

## 2. 現行アプリの実態(コード確認済み)

`ZackYuta/MediCount` を確認した結果:

- 技術: SwiftUI + SwiftData、最低 iOS 17.0、バンドルID `YutaZacky.MediCount`
- データ構造: `MedicineGroup`(薬の種類=名前) → `Medicine`(「◯本目」) → `UsageHistory`(服用履歴)
- **未実装**: StoreKit(課金)、通知、ウィジェット、CloudKit。つまり**有料機能はすべて新規実装**になる
- **「人」の概念がない**: ファミリー(複数人管理)にはプロフィール用のモデルを新設し、既存データを「デフォルトの1人」に紐づける移行が要る
- ネットワーク通信: 最新バージョン確認のための iTunes lookup のみ(ユーザーデータは送らない)。「外部送信なし」の方針は維持できる
- `AppVersion` モデルは `@Attribute(.unique)` を使う。**iCloud同期(CloudKit)とは相性が悪く**、同期を提供しない判断と整合する
- ⚠ `MediCount.entitlements` に **HealthKit(health-records含む)が有効**だが、コード上は HealthKit を使っていない(`Info.plist` にも利用目的文言なし)。**外すことに決定**(審査での説明が必要になり、プライバシー表記とも食い違うため)。実施時は、entitlements の該当キー削除に加え、Apple Developer の App ID で HealthKit capability を外し、プロビジョニングプロファイルを再生成する

## 3. 価格設計

### 3.1 価格と手取り概算

| 商品 | 日本 | 手取り(日本、税10%込み価格から控除、手数料15%) | 海外(米国基準) | 手取り(米国、手数料15%) |
|---|---|---|---|---|
| ファミリー | ¥600 | 約¥464 | $5.99 | 約$5.09 |
| プロ | ¥1,200 | 約¥927 | $11.99 | 約$10.19 |
| セット | ¥1,500 | 約¥1,159 | $14.99 | 約$12.74 |

- 米国は消費税が別建て(Appleが徴収・納付)のため、価格の85%がほぼ手取り。
- **プロの米国価格は $11.99 に決定**。日本の比率(ファミリー:プロ = 1:2)と揃い($5.99:$11.99)、セットとの差が縮まってセットへ誘導しやすい。
- **「世界一律で米国に合わせる」について**: App Store の仕組み上、基準ストアフロントを米国にすると、他国は為替・税を反映した価格が自動設定される(同額にはならない)。各国の価格を固定したい場合は国別に手動設定する。米国以外は**自動換算に任せる**のが現実的。
- 価格帯の可否: ¥600 / ¥1,200 / ¥1,500、$5.99 / $11.99 / $14.99 が App Store Connect の価格帯に存在するか、**実際に選択して確認**する。
- Small Business Program(手数料15%)の加入状況によって手取りが変わる(未加入なら手数料30%)。確認手順は別途案内。

### 3.2 価格についての注意

- 競合の年額(約¥2,500)と比べ、セット¥1,500は買い切りとして「1年以内に元が取れる」水準で、訴求は成り立つ。
- 一方、近い競合(Inhaler Counter)は評価数が数件、課金は$2.99の投げ銭のみで、**支払意思額の裏付けはない**。
- **高く始めて下げる方が、安く始めて上げるより安全**。値下げは自由だが、先に買った人の不満が出る。リリース記念価格(期間限定の値引き)として運用する案もある。
- **補完商品(買い足し割引)を作らないため、ファミリーを買った後にプロも買うと合計¥1,800(セット¥1,500より¥300高い)**になる。購入画面で「セットがお得」と明示して、最初からセットを選んでもらう導線にする。不満の声が多ければ、補完商品を追加する。

## 4. プラン設計

### 4.1 構造(独立した2つの権利+セット)

```
ファミリー権利(isFamily)   プロ権利(isPro)
        \                      /
          セット = 両方を付与
```

- ファミリーとプロは**独立**。セットは両方を付与する。
- 商品は3つ: `family`, `pro`, `set`(すべて非消耗型)。
  - 権利判定は `isFamily = family | set`、`isPro = pro | set`。
- ファミリーの人数は**5人固定**。追加枠は、要望が出た時点で非消耗型商品として追加する(消耗型にすると復元できず、機種変更や再インストールで枠が消えるため避ける)。追加が必要になる場合に備え、人数上限は定数として1箇所で管理する。
- 返金でファミリー権利が失われた場合、既に作成済みのプロフィールは**閲覧・編集のみ可、新規追加不可**にするなど、データを消さない扱いにする。
- 「ファミリー+プロ」を買う人が多く、**セットが売れ筋になる**想定(8章の試算も同じ)。

### 4.2 機能の割り振り案

| 機能 | 無料 | ファミリー ¥600 | プロ ¥1,200 | セット ¥1,500 |
|---|:-:|:-:|:-:|:-:|
| 残量カウント・服薬記録・履歴・編集 | ○ | ○ | ○ | ○ |
| 登録できる薬の数 | 無制限(現行どおり) | 無制限 | 無制限 | 無制限 |
| 家族・複数人のプロフィール | 1人 | **5人** | 1人 | 5人 |
| 残りわずか通知(基本) | ○ | ○ | ○ | ○ |
| 在庫切れ日の予測 | - | - | ○ | ○ |
| 服薬リマインダー | - | - | ○ | ○ |
| ホーム/ロック画面ウィジェット | - | - | ○ | ○ |
| 医師向けレポート出力(PDF/CSV) | - | - | ○ | ○ |
| データの書き出し/読み込み(ファイル) | - | - | ○ | ○ |
| アプリアイコン・テーマ変更 | - | - | ○ | ○ |

- **薬の登録数は無料版も無制限のまま**(現行機能を取り上げない)。したがって有料機能はすべて新規機能になる。
- ファミリーの価値は「人数」、プロの価値は「便利さ」。ファミリー単体(¥600)は複数人管理、プロ単体(¥1,200)は便利機能。
- ファミリーの価値が人数のみになるため、**¥600の納得感を左右するのは、人ごとの切り替え画面の使いやすさ**(人の切替、人ごとの薬一覧、家族への見せ方)。
- iCloud同期の代わりに、**ファイルでの書き出し/読み込み**を提供する(端末内保存の方針は維持)。機種変更時は、iOS標準のバックアップにアプリデータが含まれるかを実機で確認し、案内文を用意する。
- 「基本の残りわずか通知」は無料に残す(競合の有料機能のうち、最も乗り換え理由になるため)。
- 未実装の機能は**リリース順に出す**。購入前に実際に使えない機能を売らない。

### 4.3 既存ユーザーの扱い(重要)

- 現行バージョンで使えている機能(複数の薬・複数本の管理など)を有料に移すと、低評価レビューの原因になる。
- 対策:
  1. **登録数の上限を設けない**ため、現行機能は誰でも無料のまま使える。この点でグランドファザリング(`AppTransaction` の `originalAppVersion` 判定)は**原則不要**になった。
  2. 有料化は**新機能の追加と同時**に行い、「今までの機能はそのまま、新機能が有料」と説明する。
  3. 既存データは「デフォルトの1人」のプロフィールに紐づけて移行する(Phase 2)。
  4. 将来、現行機能の一部を有料側へ移したくなった場合のみ、`originalAppVersion` による判定を導入する。

## 5. 名称と訴求

- 「ファミリー」は Apple の「ファミリー共有」と紛らわしい。画面では **「ファミリー(家族の分も管理)」** のように説明を併記する。
- **Appleのファミリー共有は有効にしない**(全商品)。
- 訴求コピー例:
  - 「サブスクなし。1回の購入でずっと使えます」
  - 「データは端末内に保存。広告も表示しません」
  - 「プロなら、薬がなくなる日を先回りでお知らせ」
- セットを「いちばんお得」と明示する(単品合計¥1,800に対し¥1,500)。

## 6. 実装計画

### Phase 0: 事前確認

- App Store Connect で価格帯(3.1の全商品)の選択可否を確認
- Small Business Program(手数料15%)の加入状況、有料アプリ契約・口座・税務情報を確認(本人が確認中)

### Phase 2: 機能の追加と解放(優先順)

2. 在庫切れ日の予測、ウィジェット(プロ)
3. 服薬リマインダー(通知の許可フローを含む)
4. 医師向けレポート出力、データの書き出し/読み込み
5. テーマ/アイコン変更

### Phase 3: 公開面の更新
- `index.html` に「料金」セクションを追加(無料/ファミリー/プロ/セットの比較表、買い切りの強調)
- App Store 説明文、スクリーンショット、アプリ内課金の表示名・説明の登録
- プライバシーポリシー: iCloud同期を提供しないため**「外部送信なし」の記載は維持できる**。通知・ウィジェットはローカル処理のみと明記する程度で足りる。解析SDKは入れない方針を維持

## 7. 計測と判断基準

アプリ内に解析を入れない方針のため、App Store Connect の標準指標を使う。

| 指標 | 見る場所 | 目安・判断 |
|---|---|---|
| ダウンロード数 | App Analytics | 基準値の把握 |
| 商品別の購入数 | Sales and Trends | セット/プロ/ファミリーの比率 |
| 課金率(購入数/初回DL) | 上記から算出 | 高価格のため1〜2%を目安に置き、開始後に補正 |
| 評価・レビュー | App Store | 課金導入後の評価低下がないか |
| 返金 | Sales and Trends | 高い場合は説明不足を疑う |

- リリース後 **4〜8週間**は価格を固定して観察する。
- 判断例:
  - 課金率が極端に低い → 価格(特にプロ)を下げる/リリース記念価格を設定する。
  - セットばかり売れる → 想定どおり。単品の位置づけは維持する。
  - ファミリー単品がほぼ売れない → 人数需要が小さい。セットへの統合を検討。
  - 「5人では足りない」「買い足しが割高」という声が多い → 人数の追加枠、補完商品を追加する。
  - 評価が下がる → 現行機能を有料側へ移していないか、新機能の不具合がないか確認。

## 8. 収益の目安(仮定のモデル)

| 仮定 | 値 |
|---|---|
| 新規DL(日本、年間) | 3,000 |
| 課金率 | 2% → 60人 |
| 内訳 | ファミリー 25% / プロ 25% / セット 50% |

- ファミリー15人 × ¥464 ≒ ¥6,960
- プロ15人 × ¥927 ≒ ¥13,905
- セット30人 × ¥1,159 ≒ ¥34,770
- 合計 ≒ **約5.6万円/年**

高価格により課金率が1.5%に下がれば約4.2万円/年。いずれにせよ、**収益よりも、保守コストを抑えて信頼とレビューを積む設計**が現実的。DL数を増やす施策(ASO・紹介ページ・レビュー導線)の効果が最も大きい。

## 9. リスクと対策

| リスク | 対策 |
|---|---|
| 価格が高く課金率が低い | 4〜8週間の観察、記念価格での値引き運用 |
| 既存ユーザーの反発 | 現行機能は無料のまま(登録数も無制限)、新機能と同時の有料化 |
| 審査リジェクト | 購入の復元、商品説明の明確化、未実装機能を売らない、未使用HealthKit権限の削除 |
| 買い足すと割高になる不満 | セットを「いちばんお得」と明示。声が多ければ補完商品を追加 |
| 人モデル追加時のデータ移行不具合 | SwiftDataの軽量マイグレーションで検証、既存データでのテストを必須に |
| 医療表現の問題 | 効能の断定を避ける |
