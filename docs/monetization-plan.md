# 服用記録カウンター 買い切り2プラン計画(ファミリー / プロ)

作成日: 2026-10-26 / 対象: iOSアプリ「服用記録カウンター」

## 1. 方針サマリ

| 項目 | 内容 |
|---|---|
| 課金モデル | 買い切り(非消耗型)2種。サブスクなし、バナー広告なし |
| ファミリー | 日本 ¥400 / 海外 $3.99 |
| プロ | 日本 ¥800 / 海外 $7.99 |
| 差別化軸 | 「データを外部送信しない」「広告なし」「サブスクなし」 |
| 最重要の配慮 | **既存ユーザーの現行機能は取り上げない**(グランドファザリング) |

競合調査(別途実施)では、日本の服薬アプリは年額2,500円前後・月額500〜600円・広告削除300円が相場で、吸入薬・点鼻薬に特化した日本語アプリは見当たらなかった。買い切り¥800は年額相当より安く、「一度払えばずっと使える」と訴求できる。

## 2. 価格の確認事項

- 価格帯: JPY 400 / 800、USD 3.99 / 7.99 はいずれも App Store の標準価格帯にある想定。App Store Connect で選択可否を最終確認する。
- 「約8ドル」は **$7.99** を推奨(端数価格の慣行に合わせる)。
- 手取り概算(日本、消費税10%込み価格から控除し、Small Business Program の手数料15%を想定):
  - ¥400 → 約¥310 / ¥800 → 約¥620
  - $3.99 → 約$3.39 / $7.99 → 約$6.79(税・為替前)
- Small Business Program(年間収益100万ドル以下で手数料15%)に申請済みか確認する。未申請なら手数料30%で計算し直す。

## 3. プラン設計

### 3.1 階層構造(推奨)

```
無料  <  ファミリー(¥400)  <  プロ(¥800 = ファミリー全機能を含む)
```

- **プロはファミリーの上位互換**にする。ファミリー購入者がプロの機能だけ欲しい場合に、二重課金にならないようにする。
- ファミリー購入者向けに **「プロへアップグレード」(¥400 / $3.99)** を別商品として用意し、合計が ¥800 を超えないようにする。
  - 商品は3つ: `family`, `pro`, `pro_upgrade_from_family`
  - 画面では購入状態によって見せる商品を切り替える(無料→`family`/`pro`、ファミリー→`pro_upgrade_from_family`)。

### 3.2 機能の割り振り案

現行アプリの機能は公開ページの記載(残量管理・服薬記録・複数本管理・履歴確認/編集)から把握している。**実装前に現行の無料機能を棚卸しすること。**

| 機能 | 無料 | ファミリー | プロ |
|---|:-:|:-:|:-:|
| 残量カウント・服薬記録・履歴 | ○ | ○ | ○ |
| 登録できる薬の数 | 2件 | **無制限** | 無制限 |
| 家族・複数人のプロフィール | 1人 | **最大5人** | 最大5人 |
| 残りわずか通知(しきい値1つ) | ○ | ○ | ○ |
| 在庫切れ日の予測 | - | - | **○** |
| 服薬リマインダー | - | - | **○** |
| ホーム/ロック画面ウィジェット | - | - | **○** |
| iCloud同期・バックアップ | - | - | **○** |
| 医師向けレポート出力(PDF/CSV) | - | - | **○** |
| アプリアイコン・テーマ変更 | - | - | **○** |

設計の考え方:
- **ファミリー(¥400)は「量」を解放する**: 薬の数と人数。家族の分も管理する人が最も課金理由を理解しやすい。
- **プロ(¥800)は「便利さと安心」を解放する**: 通知・予測・ウィジェット・同期・レポート。競合が有料側に置いている領域で、残量不安の解消という本アプリの価値の延長にある。
- **基本的な残量通知は無料に残す**。競合の有料機能のうち一番の乗り換え理由になるため。
- 新規機能(予測・リマインダー・ウィジェット・iCloud・レポート)は未実装なら **リリース順に出す**。購入前に実際に使えない機能を売らない。

### 3.3 既存ユーザーの扱い(重要)

- 現行バージョンで使えている機能(複数本管理など)を有料に移すと、低評価レビューの原因になる。
- 対策:
  1. 課金導入前の最終バージョン以前のユーザーは、StoreKit 2 の `AppTransaction` の `originalAppVersion` で判定し、**現行機能を無料のまま維持**する。
  2. 登録数の上限は、既存ユーザーの既存データには適用しない(新規追加分にだけ適用する等)。
  3. 有料化は **新機能の追加と同時に**行い、「今までの機能はそのまま、新機能がプロ」と説明する。
- 判定ロジックは小さく保つ(アプリの起動時に1回判定してキャッシュ)。

## 4. 名称と訴求

- 「ファミリー」は Apple の「ファミリー共有」と紛らわしい。画面上は **「ファミリー(家族の分も管理)」** のように説明を併記する。
- ファミリー共有(Apple機能)を商品で有効にするかは判断が必要:
  - 有効にすると、購入者の家族が追加購入なしで使えるため、ファミリープランの価値は上がるが、収益は減る。
  - 推奨: **ファミリー・プロとも初期は無効**。ユーザーの要望が多ければ後から検討する。
- 訴求コピー例:
  - 「サブスクなし。1回の購入でずっと使えます」
  - 「データは端末内に保存。広告も表示しません」
  - 「プロなら、薬がなくなる日を先回りでお知らせ」
- 買い切りの強調は、紹介ページとApp Storeのスクリーンショットの両方に入れる。

## 5. 実装計画

### Phase 0: 事前確認(1〜2日)
- 現行機能の棚卸しと、無料/有料の最終割り振りの確定
- App Store Connect で価格帯(¥400/¥800、$3.99/$7.99)の選択可否を確認
- Small Business Program の申請状況、有料アプリ契約・銀行口座・税務情報の登録状況を確認

### Phase 1: 課金基盤
- StoreKit 2 で非消耗型3商品(`family`, `pro`, `pro_upgrade_from_family`)を実装
- **購入の復元ボタン**(App Store審査で必須)
- 購入状態(Entitlement)の一元管理。画面側は `isFamily`, `isPro` のみを参照
- 既存ユーザーのグランドファザリング判定
- StoreKit Testing(Xcodeのローカル環境)とサンドボックスで、購入・復元・アップグレード・返金を検証

### Phase 2: 機能の追加と解放(優先順)
1. 薬の登録数制限、複数人プロフィール(ファミリー)
2. 在庫切れ日の予測、ウィジェット(プロ)
3. 服薬リマインダー(プロ)
4. 医師向けレポート出力(プロ)
5. iCloud同期(プロ、最後。データ移行とコンフリクト処理が重く、既存の「外部送信なし」表記の見直しも要る)

### Phase 3: 公開面の更新
- `index.html` に「料金」セクションを追加(無料/ファミリー/プロの比較表、買い切りの強調)
- `privacy.html` の更新(下記6参照)
- App Store 説明文、スクリーンショット、アプリ内課金の表示名・説明の登録

## 6. プライバシーポリシー・規約の更新

- 現行は「ユーザー情報は端末内のみに保存、外部送信なし」。課金だけでは変更不要だが、次の場合は更新が必要:
  - **iCloud同期を入れる場合**: 「ユーザーが同期を有効にした場合のみ、AppleのiCloudにデータが保存される」旨を追記し、第2・3項の「外部送信なし」表現と矛盾しないようにする。
  - 解析SDKを入れる場合: 収集項目を明記(原則入れない方針を推奨)。
- 現行の改定条項に従い、「新バージョンのApp Store内アプリサイトで周知する」手順を実施する。
- 医療的な効果を断定する表現は避ける(「医師との相談に役立つ」程度に留める)。

## 7. 計測と判断基準

アプリ内に解析を入れない方針のため、App Store Connect の標準指標を使う。

| 指標 | 見る場所 | 目安・判断 |
|---|---|---|
| ダウンロード数 | App Analytics | 基準値の把握 |
| 課金回数(商品別) | Sales and Trends | ファミリーとプロの比率 |
| 課金率(購入数/初回DL) | 上記から算出 | 1〜3%程度を現実的な目安として置き、開始後に補正 |
| 評価・レビュー | App Store | 課金導入後の評価低下がないか |
| 返金 | Sales and Trends | プロが高い場合は説明不足を疑う |

- 初回リリース後 **4〜8週間**は価格を変えずに観察する。
- 判断例:
  - ファミリーだけが売れてプロが伸びない → プロの機能(特にウィジェット・予測)の訴求を強化、またはアップグレード価格を見直す。
  - プロばかり売れてファミリーが伸びない → ファミリーを残す意味が薄いため、統合や価格調整を検討する。
  - 評価が下がる → グランドファザリングの漏れ、機能の取り上げがないか確認する。

## 8. 収益の目安(仮定のモデル)

実測値がないため、あくまで感度の確認用。

| 仮定 | 値 |
|---|---|
| 新規DL(日本、年間) | 3,000 |
| 課金率 | 2% → 60人 |
| 内訳 | ファミリー 40% / プロ 60% |
| 手取り | ファミリー約¥310 / プロ約¥620 |

- ファミリー24人 × ¥310 ≒ ¥7,400
- プロ36人 × ¥620 ≒ ¥22,300
- 合計 ≒ **約3万円/年**

結論: ニッチなアプリなので、収益だけを目的にすると大きくはならない。**開発・保守コストを抑え、レビューと信頼を優先して長く使われる設計**が現実的。DL数を増やす施策(ASO・紹介ページ・レビュー対応)が収益に最も効く。

## 9. リスクと対策

| リスク | 対策 |
|---|---|
| 既存ユーザーの反発 | グランドファザリング、新機能と同時の有料化 |
| 審査リジェクト | 購入の復元、商品説明の明確化、未実装機能を売らない |
| 二重課金の不満 | プロ=ファミリーの上位互換、アップグレード商品の用意 |
| iCloud同期のデータ損失 | 最後に実装、ベータ検証、バックアップ手順の明記 |
| 医療表現の問題 | 効能の断定を避ける |
| 為替・各国価格のズレ | 主要国は価格帯を確認、手動調整は後回し |

## 10. 未決事項(要判断)

1. 無料版の薬登録数は2件で良いか(現行で複数登録している既存ユーザーの割合は?)
2. ファミリーの人数上限は5人で良いか
3. iCloud同期をプロに含めるか(実装コストが大きいため、別の機能で代替してもよい)
4. ファミリー共有(Apple機能)を有効にするか(推奨は初期は無効)
5. 海外向けは $3.99 / $7.99 に固定するか、国別に調整するか
6. Small Business Program の申請状況
